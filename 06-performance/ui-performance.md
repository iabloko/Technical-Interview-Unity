# Производительность UI (uGUI)

uGUI (`Canvas` + `CanvasRenderer`) — частый источник CPU-нагрузки из-за перестроения геометрии (batching/rebuild). Диагностика — [Profiler](../03-unity-core/profiler.md) (`Canvas.SendWillRenderCanvases`, `Canvas.BuildBatch`).

## Главное: Canvas rebuild

`Canvas` пересобирает (rebatch) геометрию своих элементов, когда **меняется любой** его потомок (позиция, цвет, текст, активность). Пересборка затрагивает **весь** Canvas, а не один элемент.

Вывод — **разбивать Canvas по частоте обновления**:
- Статика (фон, рамки HUD) — отдельный Canvas, не перестраивается.
- Часто меняющееся (счёт, полоса здоровья) — отдельный Canvas.
- Интерактив (кнопки) — отдельный Canvas.

Так изменение счёта не заставляет пересобирать кнопки и фон.

## Другие частые проблемы

- **`Raycast Target`** включён по умолчанию у `Image`/`Text`. Отключать на элементах, которым не нужны клики (фоны, иконки) — меньше работы для системы рейкастов ввода.
- **`LayoutGroup`** (`Horizontal/Vertical/Grid`) пересчитывается при любом изменении детей — дорого при многих элементах в рантайме. Для динамических списков — ручное позиционирование или пул.
- **Текст**: обновлять `TMP_Text.SetText(StringBuilder)` без склейки строк каждый кадр (см. [строки](../01-csharp/strings.md)).
- **Анимация полупрозрачности**: менять `alpha` через `CanvasGroup`, а не цвет каждого `Image` — `CanvasGroup` не вызывает rebuild геометрии.
- **Overdraw** от наложенных полупрозрачных слоёв UI — особенно критично на мобиле (см. [mobile](mobile-optimization.md)).
- **Большие списки** (инвентарь, лента) — виртуализация/пул элементов ([object pooling](../03-unity-core/object-pooling.md)), а не сотни активных объектов.

## UI Toolkit (кратко)

Современная альтернатива uGUI: retained-модель на UXML/USS, ориентирована на редакторные и runtime-интерфейсы, со своим механизмом обновления (не Canvas rebatch). Для нового UI рассматривают как замену; в существующих проектах часто сосуществует с uGUI.

- Как разбивать Canvas по частоте обновления.
- Зачем отключать `Raycast Target`.
- Почему `LayoutGroup` дорог и чем заменить.
- Как анимировать прозрачность UI без rebuild (`CanvasGroup`).
