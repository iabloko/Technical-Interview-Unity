# URP — Universal Render Pipeline

**URP (Universal Render Pipeline)** — готовый рендер-пайплайн Unity, построенный на **SRP (Scriptable Render Pipeline)**. Это «золотая середина» между старым **Built-in** пайплайном и тяжёлым **HDRP**: хорошая графика при высокой производительности на широком спектре устройств.

## Плюсы URP

- **Производительность на любом железе.** Оптимизирован от мобильных и VR до ПК/консолей. Single-pass forward-рендер даёт меньше проходов и draw call'ов.

  > **Forward-рендер** — освещение считается прямо при отрисовке каждого объекта (шейдер обсчитывает влияющие на него источники света). Противоположность — *deferred*: сначала геометрия пишется в G-buffer, затем свет считается отдельным полноэкранным проходом.
  >
  > **Single-pass** — все источники света для объекта обсчитываются за **один** проход шейдера. В старом Built-in forward каждый дополнительный per-pixel свет добавлял **отдельный** проход отрисовки объекта (→ лишние draw call'ы). URP делает это в одном проходе (с лимитом на число источников) → меньше проходов и нагрузки на CPU.
  >
  > **Forward+** (Forward Plus, в URP с Unity 2022.2) — улучшенный forward: экран делится на тайлы/кластеры, и источники света отсекаются **по тайлам экрана**, а не по объектам. Это снимает жёсткий лимит на число per-pixel источников на объект — в сцене можно держать **много** динамического света без лишних проходов. Цена — дополнительная память и вычисления на отсечение света.
- **Кроссплатформенность.** Один пайплайн для всех целей: mobile, PC, консоли, WebGL, XR — без отдельной настройки под каждую платформу.
- **SRP Batcher.** Сильно снижает CPU-overhead на отрисовку: батчинг по шейдерам/материалам ускоряет сцены с большим числом объектов.

  > **Важно:** SRP Batcher **не уменьшает число draw call'ов** (в отличие от static/dynamic batching, которые склеивают меши). Он снижает **стоимость** каждого вызова на CPU.
  >
  > Обычно перед каждым draw call'ом CPU заново настраивает состояние GPU (привязка свойств материала, constant buffers) — смена материала дорогая. SRP Batcher держит данные материалов в постоянных буферах на стороне GPU, поэтому объекты с **одним вариантом шейдера** (даже с разными материалами) рисуются подряд, обновляя только per-object данные. Меньше работы на render-потоке CPU.
  >
  > Условия: шейдер должен быть **SRP Batcher-совместим** (шейдеры URP/HDRP — да; кастомные требуют корректного `CBUFFER UnityPerMaterial`). `MaterialPropertyBlock` ломает совместимость для объекта.
- **Shader Graph.** Визуальный редактор шейдеров — можно собирать материалы без ручного HLSL.
- **Renderer Features / Scriptable Render Passes.** Рендер расширяется кастомными проходами (outline, custom blur и т.п.) без правки движка.
- **Встроенный post-processing (Volume framework).** Эффекты (bloom, tonemapping, DOF) настраиваются через тома, без отдельного пакета.
- **2D Renderer.** Нативная поддержка 2D-света и теней.
- **Camera Stacking.** Наложение камер (например, отдельная камера для оружия/UI) из коробки.
- **Оптимизация под XR.** Single-pass instanced рендеринг для VR/AR.
- **Будущее Unity.** URP — рекомендуемый и развиваемый пайплайн по умолчанию; Built-in считается устаревающим.

## URP vs HDRP vs Built-in (кратко)

| Критерий | Built-in | **URP** | HDRP |
|---|---|---|---|
| Платформы | все | все (mobile→PC) | только high-end PC/консоли |
| Производительность | средняя | **высокая, масштабируемая** | требовательный |
| Качество графики | базовое | хорошее | максимальное (AAA) |
| Настройка/расширение | ограничено | **Shader Graph + Renderer Features** | максимум возможностей |

> Когда выбирать URP: мобильные/VR-проекты, кроссплатформенные игры, когда нужен баланс графики и FPS. HDRP — только для фотореалистичных проектов на мощном железе.
