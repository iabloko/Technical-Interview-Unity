# Жизненный цикл MonoBehaviour

Unity сама вызывает «event-функции» компонента в строго определённом порядке. Понимание этого порядка — один из самых частых вопросов на собеседовании.

## Порядок вызова (упрощённо)

```
Awake → OnEnable → Start
   │
   └─ каждый кадр:
        FixedUpdate (0..n раз) → обработка физики → OnTrigger/OnCollision
        обработка ввода
        Update → yield-корутины → LateUpdate
        рендер (OnGUI и т.п.)
   │
OnDisable → OnDestroy
```

## Основные методы

| Метод | Когда вызывается | Сколько раз | Для чего |
|---|---|---|---|
| `Awake` | при загрузке экземпляра, до любого `Start` | один раз | самоинициализация, `GetComponent` |
| `OnEnable` | каждый раз при включении объекта/компонента | много раз | подписка на события |
| `Start` | перед первым `Update`, только если компонент включён | один раз | инициализация с опорой на другие объекты |
| `FixedUpdate` | с фиксированным шагом (физика) | 0..n за кадр | физика, `Rigidbody` |
| `Update` | каждый кадр | каждый кадр | основная игровая логика |
| `LateUpdate` | каждый кадр, после всех `Update` | каждый кадр | камера, дослеживание |
| `OnDisable` | при выключении объекта/компонента | много раз | отписка от событий |
| `OnDestroy` | при уничтожении объекта | один раз | освобождение ресурсов |

## Awake vs Start (ключевое различие)

| | `Awake` | `Start` |
|---|---|---|
| Когда | сразу при создании, **до всех** `Start` | перед первым кадром, **после всех** `Awake` |
| Если компонент выключен | **всё равно** вызовется (объект активен) | **не** вызовется, пока не включат |
| Типичное применение | настроить **себя**, получить ссылки | обратиться к **другим** объектам (они уже прошли `Awake`) |

> Правило: в `Awake` — собственная инициализация и кэш `GetComponent`; в `Start` — обращение к уже инициализированным чужим компонентам.

## Update / FixedUpdate / LateUpdate

- **`Update`** — раз в кадр; частота **плавающая**, зависит от FPS → использовать `Time.deltaTime`.
- **`FixedUpdate`** — фиксированный шаг (по умолчанию 0.02 с); вся **физика** и силы к `Rigidbody` здесь; за один кадр может не вызваться ни разу или несколько раз → `Time.fixedDeltaTime`.
- **`LateUpdate`** — после всех `Update`; для логики, зависящей от уже обновлённых объектов (камера следует за игроком).

```csharp
public class Mover : MonoBehaviour
{
    [SerializeField] private Rigidbody _rb;

    private void Awake() => _rb = GetComponent<Rigidbody>(); // ссылка на себя
    private void Update() => transform.Rotate(0, 90 * Time.deltaTime, 0); // визуал
    private void FixedUpdate() => _rb.AddForce(Vector3.forward); // физика
}
```

## Порядок между разными скриптами

- Порядок `Awake`/`Start` **между разными объектами не гарантирован**. Если нужна детерминированность — задать **Script Execution Order** (Project Settings → Script Execution Order) или явные ссылки/события.

## Точки корутин относительно цикла

- `yield return null` — продолжить после `Update` следующего кадра;
- `yield return new WaitForFixedUpdate()` — после `FixedUpdate`;
- `yield return new WaitForEndOfFrame()` — после рендера кадра.

## Частые вопросы на собеседовании

1. **Назови порядок вызова основных event-функций.**
2. **Чем `Awake` отличается от `Start`?** (время вызова + поведение при выключенном компоненте)
3. **Где писать физику и почему?** (`FixedUpdate` — фиксированный шаг)
4. **Зачем нужен `LateUpdate`?** (камера/логика после всех `Update`)
5. **Сколько раз вызывается `OnEnable`/`OnDisable` против `Awake`/`OnDestroy`?**
6. **Гарантирован ли порядок `Awake` между разными объектами?** (нет; Script Execution Order)
7. **Почему в `Update` используют `Time.deltaTime`?** (кадр плавающей длительности)
