# ScriptableObject

`ScriptableObject` — наследник `UnityEngine.Object`, экземпляр которого существует как **ассет в проекте**, а не как компонент на сцене. Контейнер данных (и/или логики), живущий независимо от объектов сцены.

```csharp
[CreateAssetMenu(menuName = "Config/EnemyConfig")]
public class EnemyConfig : ScriptableObject
{
    public float MaxHealth;
    public float Speed;
    public GameObject Prefab;
}
```

## Чем отличается от MonoBehaviour

| | MonoBehaviour | ScriptableObject |
|---|---|---|
| Где живёт | на `GameObject` в сцене | ассет в проекте |
| Lifecycle | `Awake`/`Update`/… | `OnEnable`/`OnDisable`/`OnDestroy`, без покадрового `Update` |
| Экземпляры | по одному на объект | один ассет общий для всех ссылающихся |
| Назначение | поведение объекта сцены | данные, конфиги, общее состояние |

## Зачем (use cases)

- **Конфиги/данные (data-driven design).** Параметры врагов, оружия, уровней — в ассетах, не в коде и не в префабах. Геймдизайнер правит без программиста.
- **Экономия памяти.** Один ассет конфига общий для тысяч экземпляров — данные не дублируются в каждом префабе.
- **Разделяемое состояние без синглтонов.** Ассет-«переменная» (например, текущее здоровье игрока), на который ссылаются и UI, и геймплей — слабая связанность (см. [coupling](../02-architecture/coupling-decoupling.md)).
- **SO-based event channels.** Событие как ассет: издатель вызывает `Raise()`, подписчики (на разных сценах) реагируют, не зная друг о друге.

## Подводные камни (важно)

- **Изменения в рантайме сохраняются в редакторе.** В Editor правка полей SO во время Play остаётся в ассете после остановки. В билде изменения живут только в памяти: на диск не записываются, а если на ассет не осталось ссылок и он выгружен (смена сцены, `Resources.UnloadUnusedAssets`), при следующей загрузке SO вернётся к исходным значениям. Поэтому SO как хранилище рантайм-состояния («переменная»-ассет) требует явной инициализации. Для рантайм-копии — `Instantiate(so)`.
- `OnEnable` у SO вызывается при загрузке ассета и после domain reload. При отключённом domain reload (Enter Play Mode Options) вход в Play Mode `OnEnable` не вызывает, и состояние SO переходит из предыдущей сессии. Сбрасывать его явно: статический метод с `[InitializeOnEnterPlayMode]` (редактор), подписка на `EditorApplication.playModeStateChanged` или инициализация из точки входа игры.
- Ссылку на сценовый объект в SO положить нельзя (SO — ассет, не знает о сцене).

## Что спрашивают на собеседовании

- Чем `ScriptableObject` отличается от `MonoBehaviour` и от обычного `[Serializable]`-класса.
- Почему SO экономит память (общий ассет vs дублирование в префабах).
- Как SO помогает уменьшить связанность (event channels, shared data).
- Почему правки SO в Play Mode «остаются» в редакторе.
