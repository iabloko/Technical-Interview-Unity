# Asset Loading: Resources vs AssetBundles vs Addressables

Три способа загружать ассеты в рантайме в Unity. Различаются тем, **где живут ассеты** (в билде / отдельно / в CDN), **как ими управляют** (вручную / автоматически) и **можно ли обновлять контент** после релиза.

---

## Resources

«Магическая» папка `Assets/Resources/`. Всё, что в ней лежит, **попадает в билд целиком** (вне зависимости от того, ссылается ли кто на ассет) и загружается по строковому пути.

```csharp
// синхронно
var prefab = Resources.Load<GameObject>("Enemies/Goblin");
var instance = Object.Instantiate(prefab);

// асинхронно
var req = Resources.LoadAsync<Texture2D>("UI/Logo");
yield return req;
var tex = req.asset as Texture2D;

// освобождение
Resources.UnloadAsset(prefab);          // конкретный ассет
Resources.UnloadUnusedAssets();          // дорогая операция, чистит всё неиспользуемое
```

**Плюсы:** простой API, ничего настраивать не надо.

**Минусы:**
- **всё содержимое попадает в билд** → раздувает размер APK/IPA;
- индекс Resources строится при запуске → **медленный старт** на больших проектах;
- ручное управление памятью (`UnloadUnusedAssets` — дорогая);
- **нельзя обновлять контент** без пересборки приложения;
- строковые пути → легко ошибиться, нет рефакторинга.

> Официально не рекомендуется для продакшна — только для прототипов / очень мелких ассетов.

---

## AssetBundles

Ручная упаковка ассетов в **отдельные файлы-бандлы**, которые собираются билд-пайплайном и могут лежать локально или на **CDN**. Это базовый механизм, поверх которого работают Addressables.

```csharp
// сборка (Editor)
BuildPipeline.BuildAssetBundles("Assets/AssetBundles",
    BuildAssetBundleOptions.None, BuildTarget.StandaloneWindows);

// рантайм: скачать + загрузить + использовать
var req = UnityWebRequestAssetBundle.GetAssetBundle("https://cdn/.../enemies");
yield return req.SendWebRequest();
var bundle = DownloadHandlerAssetBundle.GetContent(req);

var prefab = bundle.LoadAsset<GameObject>("Goblin");
Object.Instantiate(prefab);

bundle.Unload(false); // false — оставить загруженные ассеты в памяти, true — выгрузить всё
```

**Плюсы:**
- ассеты вне основного билда → меньше размер;
- хостинг на **CDN**, обновление контента без переcборки;
- полный контроль над упаковкой и зависимостями.

**Минусы:**
- ручное управление **всем**: скачивание, кеш, версии, зависимости;
- легко получить **дублирующиеся** ассеты, если зависимости не разнесены явно;
- ручные `Unload(true/false)` — частый источник утечек или, наоборот, разрушения живых ссылок;
- много бойлерплейта, кастомный пайплайн.

---

## Addressables

Высокоуровневая обёртка поверх AssetBundles. Ассеты адресуются **строковым ключом** (address) или `AssetReference`, лежат в группах, билдятся в каталог. Поддерживает локальный и удалённый контент, делает **подсчёт ссылок** и автоматически выгружает ассеты.

```csharp
// загрузка по адресу
var handle = Addressables.LoadAssetAsync<GameObject>("Goblin");
await handle.Task;
var instance = Object.Instantiate(handle.Result);

// release — обязателен; счётчик ссылок снижается, ассет выгрузится сам
Addressables.Release(handle);

// или удобно: грузим и сразу инстанциируем
var instHandle = Addressables.InstantiateAsync("Goblin");
await instHandle.Task;
Addressables.ReleaseInstance(instHandle.Result);
```

**Плюсы:**
- async API, **автоматическое** управление зависимостями и памятью (reference counting);
- единый код для **локального и удалённого** контента (CDN, hot updates);
- группы, метки (labels), каталоги контента, профили окружений;
- встроенная аналитика, отслеживание утечек.

**Минусы:**
- свой граф зависимостей и каталог → дополнительный шаг сборки;
- забыл вызвать `Release` → утечка;
- кривая обучения чуть выше, чем у Resources.

> **Стандарт де-факто** для современного Unity. Под капотом — те же AssetBundles, но без ручной возни.

## Сравнительная таблица

| Критерий                  | Resources                  | AssetBundles      | **Addressables**                   |
|---------------------------|----------------------------|-------------------|------------------------------------|
| Где живут ассеты          | внутри билда               | отдельные файлы   | отдельные файлы (поверх бандлов)   |
| Что попадает в билд       | **всё** содержимое папки   | только что собрал | только что отмечено                |
| Локальный / удалённый     | только локально            | оба (ручной CDN)  | **оба (из коробки)**               |
| Обновление без пересборки | ❌                          | ✓ (вручную)       | ✓ (встроено)                       |
| API                       | sync + async               | manual            | **async**                          |
| Управление памятью        | ручное                     | ручное (`Unload`) | **reference counting + `Release`** |
| Зависимости               | автоматом (но всё в билде) | вручную           | **автоматом**                      |
| Сложность                 | минимальная                | высокая           | средняя                            |
| Когда выбрать             | прототип / мелочи          | редко (legacy)    | **по умолчанию**                   |

---

## Что выбрать

- **Addressables** — для нового проекта по умолчанию.
- **Resources** — только для крошечных ассетов, которые точно нужны всегда (иконки приложения, дефолтный шрифт). Для прототипов сойдёт.
- **AssetBundles напрямую** — если есть кастомный пайплайн доставки контента и нужен полный контроль; иначе предпочесть Addressables.
