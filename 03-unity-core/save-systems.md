# Сохранения и сериализация данных

Речь о **рантайм-сериализации данных игрока** (сейвы, настройки, сетевые DTO) — не путать с [сериализацией Unity](serialization.md) (инспектор, ассеты, сцены): это разные механизмы с разными правилами.

## Форматы и библиотеки

### JsonUtility (встроенный)

```csharp
string json = JsonUtility.ToJson(saveData);
var data = JsonUtility.FromJson<SaveData>(json);
```

Следует правилам Unity-сериализации (публичные поля / `[SerializeField]`, `[Serializable]` на типе).

**Плюсы:** встроен, быстрый, минимальные аллокации, работает на IL2CPP без настройки.

**Ограничения (главный вопрос на собесе):**
- **не сериализует `Dictionary`**, `HashSet`, многомерные массивы;
- **нет полиморфизма**: поле базового типа сериализуется как базовый тип (и `[SerializeReference]` не поддерживает);
- только поля, не свойства; нет nullable;
- не умеет корневой массив/примитив — нужен класс-обёртка;
- нет настроек именования, конвертеров, обработки отсутствующих полей.

### Newtonsoft Json.NET (`com.unity.nuget.newtonsoft-json`)

```csharp
string json = JsonConvert.SerializeObject(saveData, _settings);
var data = JsonConvert.DeserializeObject<SaveData>(json, _settings);
```

**Плюсы:** `Dictionary`, свойства, полиморфизм (`TypeNameHandling` / кастомные конвертеры), `JsonConverter`, контроль именования, значения по умолчанию, `JObject` для частичного разбора и миграций.

**Минусы:**
- медленнее и аллоцирует заметно больше (рефлексия) — не для горячего пути;
- на **IL2CPP** — риски от [code stripping](il2cpp-mono.md): типы, используемые только через рефлексию, вырезаются → `link.xml` / `[Preserve]`; AOT-проблемы с дженерик-комбинациями;
- `TypeNameHandling.All/Auto` на **недоверенных данных** — известный вектор атаки (десериализация произвольных типов); для сейвов с диска приемлемо ограниченно, для сетевых данных — нет.

### Бинарные форматы

- **`BinaryFormatter` — запрещён**: небезопасная десериализация (RCE-вектор), помечен obsolete в .NET; в интервью упоминать именно как анти-пример.
- Современные варианты: **MessagePack-CSharp**, **MemoryPack**, **protobuf** — компактнее и в разы быстрее JSON, со схемой/версионированием; требуют генерации кода/атрибутов (что одновременно решает AOT-проблему IL2CPP). Выбор, когда сейв большой или сериализация частая (автосейвы, реплеи, сеть).

### Сравнение

| | JsonUtility | Json.NET | MessagePack/MemoryPack |
|---|---|---|---|
| Скорость / аллокации | высокая / низкие | низкая / высокие | максимальная / минимальные |
| Dictionary, полиморфизм | нет | да | да (атрибуты/Union) |
| Читаемость файла | да (текст) | да (текст) | нет (бинарный) |
| IL2CPP | без настройки | link.xml, AOT-нюансы | source generator — без рефлексии |
| Когда | простые сейвы/настройки | сложные модели, миграции | большие/частые сейвы, сеть |

## PlayerPrefs — что это и что это не сейв

`PlayerPrefs` хранит пары ключ-значение (`int`, `float`, `string`) в платформенном хранилище (реестр на Windows, plist на iOS, xml на Android).

- Подходит: настройки (громкость, язык, качество), флаги онбординга.
- Не подходит для игровых сейвов: нет структуры и версионирования, лимиты размера, синхронная запись (`Save()` — блокирующая), легко редактируется игроком.

## Архитектура save-системы

### Отдельная модель сейва (DTO)

Сериализуется **не** доменное состояние напрямую, а отдельный DTO-слой:

```csharp
[Serializable]
public class SaveData
{
    public int Version = 3;        // версия схемы — обязательное поле с первого релиза
    public PlayerSave Player;
    public List<QuestSave> Quests;
}
```

Зачем: доменные классы свободно рефакторятся, ссылки на `UnityEngine.Object` не попадают в сейв, схема сейва меняется осознанно. Маппинг домен ↔ DTO — явный код (в Clean Architecture — на границе слоя, см. [clean-architecture](../02-architecture/clean-architecture.md)).

### Версионирование и миграции

Игрок обновил игру — его сейв старой схемы обязан загрузиться.

- В сейве — поле `Version`; при загрузке `Version < Current` → цепочка миграций `v1→v2→v3` (каждая — маленькая функция, правящая данные/JSON).
- Правила эволюции схемы: новые поля — со значениями по умолчанию; поля не удалять и не переименовывать без миграции; переименование — это миграция (прочитать старое имя, записать новое).
- Для миграций удобен разбор в `JObject` (Json.NET): правки по ключам без устаревших C#-классов каждой версии.

### Атомарная запись

Запись может прерваться (вылет, kill процесса, нехватка места) — сейв не должен быть повреждён наполовину:

```csharp
var path = Path.Combine(Application.persistentDataPath, "save.json");
File.WriteAllText(path + ".tmp", json);   // 1) пишем во временный файл
if (File.Exists(path))
    File.Replace(path + ".tmp", path, path + ".bak"); // 2) атомарная подмена + бэкап предыдущего
else
    File.Move(path + ".tmp", path);       //    первое сохранение: File.Replace требует существующий целевой файл
```

При загрузке: основной файл повреждён (исключение парсинга, проверка контрольной суммы) → откат на `.bak`.

- Писать в **`Application.persistentDataPath`** — единственный гарантированно записываемый путь на всех платформах (`dataPath` на мобильных read-only).
- Запись — асинхронно/вне кадра (автосейв не должен давать хитч; см. [время](time.md)): сериализация и IO на пуле потоков, обращение к Unity-данным — только при сборе DTO в главном потоке.

### Защита и облако

- Клиентское шифрование/подпись сейва — **обфускация**, не защита: ключ находится в билде. Реальная защита от читов — только серверное хранение/валидация.
- Облачные сейвы → **конфликты** (две девайс-версии): стратегия выбора — по времени/прогрессу/запросу к игроку — проектируется заранее, поле с метаданными (timestamp, playtime) в сейве.

## Что спрашивают на собеседовании

- Ограничения `JsonUtility` (Dictionary, полиморфизм, свойства) и когда его достаточно.
- Чем расплачиваемся за Json.NET (скорость, аллокации, stripping/AOT на IL2CPP, link.xml).
- Почему `BinaryFormatter` нельзя; что вместо него для бинарных сейвов.
- Почему `PlayerPrefs` не для игровых сейвов.
- Как версионировать сейвы и мигрировать старые (поле Version + цепочка миграций).
- Зачем отдельный DTO-слой вместо сериализации доменных объектов.
- Как не потерять сейв при вылете во время записи (temp + атомарная подмена + бэкап).
- Куда писать файлы на мобильных (`persistentDataPath`) и почему шифрование сейва — не защита.
