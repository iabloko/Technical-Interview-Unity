# Frame Debugger

Встроенный инструмент: **Window → Analysis → Frame Debugger**. **«Замораживает» один кадр** и позволяет пройти его **draw call за draw call'ом**, видя на каждом шаге, что именно и как нарисовалось. Главный инструмент для диагностики **рендера**.

## Как работает

- Включаешь `Enable` → игра ставится на паузу, в Game view виден прогрессивный набор draw call'ов.
- Слева — дерево всех вызовов отрисовки кадра (по render target / по шейдеру / по объектам).
- Шагаешь стрелками — каждый шаг добавляет один draw call к промежуточной картинке.
- Для каждого шага показывает: **render target**, **shader + variant**, **material**, **mesh**, **state** (blend/depth/stencil), **uniforms**, причину **батчинга/не-батчинга**.

## Что ключевое можно посмотреть

- **Общее число draw call'ов** и батчей за кадр.
- **Что именно** рисуется в каждом проходе и в каком порядке (opaque → skybox → transparent → UI).
- **Почему не сбатчилось**: рядом с draw call'ом указано «Different shader», «Different material», «Batcher: MaterialPropertyBlock used» и т.п. — сразу понятно, где сломан **SRP Batcher** или статический/динамический батчинг.
- **Содержимое промежуточных render target'ов** (G-buffer, тени, прозрачные) — увидеть, что попало в shadow map, в depth, в bloom-блюр.
- **Лишние / невидимые** draw call'ы — объекты, которые рисуются, но не должны (за камерой, под UI, пустые меши).
- **Состояние шейдера** на конкретном вызове: текстуры, переменные, keywords — отладка артефактов и неправильных эффектов.

## Когда использовать

- Кадр «тяжёлый» в Rendering-модуле [Profiler](profiler.md) → открыть Frame Debugger, чтобы понять *почему* много draw call'ов или батчей.
- Артефакт в постпроцессинге / шейдере — посмотреть на промежуточные RT.
- Падает SRP Batcher / GPU Instancing — найти, на чём именно «рвётся» батч.

## Что спрашивают на собеседовании

- Чем Frame Debugger отличается от Profiler (почему кадр рисуется именно так, а не где тратится время).
- Как узнать, почему draw call не объединился в батч с предыдущим.
- Как посмотреть содержимое промежуточных render target'ов (shadow map, depth, G-buffer).
- Как проверить, что кастомный проход встал в нужное место кадра.
