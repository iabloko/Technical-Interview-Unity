# Освещение: URP vs Built-in

Здесь — как считается свет в **Built-in** и **URP** пайплайнах и чем они отличаются. Базовые понятия (типы источников, запекание) у них общие; разница в том, *как* свет применяется при отрисовке.

## Как вообще работает свет (физическая модель)

Прежде чем про пайплайны — как свет ведёт себя в реальности и что из этого движок приближает.

1. **Излучение.** Источник испускает лучи (фотоны): во все стороны (point/spot) или параллельным потоком (directional — «солнце»).
2. **Попадание на поверхность.** Часть энергии луча **поглощается** (уходит в тепло), часть **отражается**, часть может **пройти насквозь** с преломлением (прозрачные материалы).
3. **Отражение зависит от материала** (формально описывается **BRDF**):
   - **диффузное (рассеянное)** — шероховатая поверхность раскидывает свет во все стороны (матовый цвет; это и есть закон Ламберта `NdotL`);
   - **зеркальное (specular)** — гладкая поверхность отражает направленно: это и блики, и отражения окружения (отсюда Reflection Probes).
4. **Отскоки (bounces).** Отражённый луч летит дальше и освещает **другие** поверхности: красная стена «подкрашивает» соседний пол. Многократные отскоки и есть **Global Illumination (GI)** — непрямой свет.
5. **Попадание в камеру.** Лучи, дошедшие до камеры, формируют картинку. Яркость пикселя = сумма всего света, пришедшего в эту точку со всех направлений (формально — *rendering equation*).

### Что из этого реально считает движок

Ключевой момент: **растеризаторы (Built-in / URP) не трассируют лучи.** Считать всё честно в реальном времени слишком дорого, поэтому рендер **приближает**:

- **Прямой свет (direct)** — честно считается в реалтайме на каждый пиксель (`NdotL` + specular), как в примерах выше. Это «первое попадание» луча от источника.
- **Непрямой свет (indirect / отскоки)** — слишком дорог для реалтайма, поэтому:
  - **запекается** в лайтмапы заранее (для статичной геометрии);
  - аппроксимируется **Light Probes** (для движущихся объектов);
  - **Reflection Probes** дают приближение зеркальных отражений.
- **Тени** — приближение факта «луч до источника перекрыт другой геометрией» через shadow maps.
- **Ray / Path tracing** — режим, где лучи и отскоки считаются честно (дорого). Причём лучи пускают **из камеры назад** в сцену — так считается только видимое. В Unity — ray tracing в HDRP либо path-traced запекание лайтмап.

> Итог: реалтайм-рендер честно считает только **прямой** свет на пиксель, а отскоки (**GI**) и отражения — заранее **запекает** или аппроксимирует пробами. Отсюда и деление на realtime / baked / mixed свет.

## Общие понятия (одинаково в обоих пайплайнах)

### Типы источников света
- **Directional** — направленный (солнце), бесконечно далёкий, освещает всю сцену под одним углом.
- **Point** — точечный, светит во все стороны от точки.
- **Spot** — прожектор, конус.
- **Area** — площадной; работает **только в запечённом** свете.

### Режимы (Light Mode)
- **Realtime** — считается каждый кадр, динамические тени, дорого.
- **Baked** — запекается в **лайтмапы** заранее; без затрат в рантайме, но только для статичной геометрии.
- **Mixed** — комбинация: прямой свет реалтайм, непрямой запечён.

### Инструменты непрямого света (GI)
- **Lightmaps** — запечённый свет/тени для статичных объектов (Progressive Lightmapper).
- **Light Probes** — непрямой свет для **движущихся** объектов.
- **Reflection Probes** — запечённые отражения.

## Built-in: как применяется свет

Два пути рендера (Camera / Graphics Settings):

- **Forward** (по умолчанию):
  - самый яркий **directional** считается per-pixel в базовом проходе;
  - каждый дополнительный **per-pixel** источник добавляет **отдельный проход отрисовки** объекта (additive pass) → лишние draw call'ы;
  - часть источников может считаться дешевле — **per-vertex** или через **сферические гармоники (SH)**;
  - число per-pixel источников ограничивает *Pixel Light Count* в Quality Settings.
- **Deferred**:
  - геометрия пишется в **G-buffer**, свет считается в экранном пространстве;
  - много источников дёшево, но больше расхода памяти/полосы; прозрачные объекты всё равно рисуются forward'ом.

### Как считается per-pixel свет (пример)

«Per-pixel» значит, что уравнение освещения вычисляется в **фрагментном шейдере для каждого пикселя**, по интерполированной нормали. Главный directional в базовом проходе считается по закону Ламберта (диффуз ∝ косинусу угла между нормалью и направлением на свет):

```hlsl
// фрагментный шейдер — выполняется для КАЖДОГО пикселя
fixed4 frag (v2f i) : SV_Target
{
    float3 N = normalize(i.worldNormal);            // нормаль, интерполированная на пиксель
    float3 L = normalize(_WorldSpaceLightPos0.xyz); // направление на directional-свет
    float  NdotL = max(0, dot(N, L));               // закон Ламберта: косинус угла

    fixed3 albedo  = tex2D(_MainTex, i.uv).rgb;     // базовый цвет поверхности
    fixed3 diffuse = _LightColor0.rgb * NdotL;      // вклад главного света
    fixed3 ambient = ShadeSH9(float4(N, 1));        // непрямой свет (сферические гармоники)

    return fixed4(albedo * (diffuse + ambient), 1);
}
```

Сравните с **per-vertex**: там `NdotL` считается в вершинном шейдере (всего на 3 вершины треугольника) и **интерполируется** по грани — дешевле, но блики и кривизна выглядят грубо. Per-pixel вычисляет свет на каждый пиксель → плавно и точно, но дороже.

## URP: как применяется свет

Настраивается в **URP Asset** (секция Lighting) и Universal Renderer.

- **Forward** (по умолчанию):
  - **Main Light** — один directional, per-pixel;
  - **Additional Lights** — настраиваются как **Per Pixel / Per Vertex / Disabled**;
  - все источники объекта считаются в **одном проходе** (нет отдельного прохода на каждый свет, как в Built-in) → дешевле по draw call'ам;
  - есть **лимит** доп. источников на объект (по умолчанию до 8, зависит от платформы и настроек Asset).
- **Forward+** (с Unity 2022.2):
  - свет отсекается **по тайлам экрана** (clustered), а не по объектам;
  - снимает лимит «N источников на объект» → много динамического света. См. [URP](urp-render-pipeline.md).
- **Deferred** (с Unity 2021.2):
  - G-buffer-путь и в URP, для сцен с большим числом источников.

### Как считается per-pixel свет в URP (пример)

Математика та же (`NdotL`, закон Ламберта на каждый пиксель), но **другой shader API** — библиотека URP `Lighting.hlsl` вместо `_LightColor0`/`ShadeSH9`. Дополнительные источники накапливаются в **цикле в одном проходе** (без отдельных additive-проходов, как в Built-in):

```hlsl
// URP: фрагментный шейдер
half4 frag (Varyings i) : SV_Target
{
    half3 N = normalize(i.normalWS);
    half3 albedo = SAMPLE_TEXTURE2D(_BaseMap, sampler_BaseMap, i.uv).rgb;

    // главный directional
    Light main = GetMainLight();
    half3 color = albedo * main.color * saturate(dot(N, main.direction));

    // дополнительные источники — тот же расчёт в цикле, один проход
    uint count = GetAdditionalLightsCount();
    for (uint li = 0; li < count; li++)
    {
        Light l = GetAdditionalLight(li, i.positionWS);
        half atten = l.distanceAttenuation * l.shadowAttenuation;     // затухание + тень
        color += albedo * l.color * saturate(dot(N, l.direction)) * atten;
    }
    return half4(color, 1);
}
```

> **Forward+** на уровне шейдера почти не отличается — тот же цикл `GetAdditionalLight`. Меняется лишь то, *как формируется список источников*: отсечение по тайлам/кластерам экрана, а не по объектам. Сам per-pixel расчёт на каждый источник идентичен.

## Тени

- Реалтайм-тени — через **shadow maps** (источник рендерит глубину сцены со своей точки).
- У **directional** теней — **каскады** (cascades): несколько карт разного разрешения по дистанции для качества вблизи.
- Параметры: дистанция теней, мягкие/жёсткие, разрешение. В URP всё это — в URP Asset; в Built-in — в Quality Settings.

## Ключевые отличия (для собеседования)

| | Built-in Forward | URP Forward |
|---|---|---|
| Доп. per-pixel источник | **отдельный проход** на объект | в **одном проходе**, но с лимитом |
| Настройка лимита света | Pixel Light Count (Quality) | URP Asset (Per Pixel/Vertex, max) |
| Много динамического света | дорого (или Deferred) | **Forward+** (clustered) |
| Где настраивается | Quality / Graphics Settings | URP Asset + Renderer |

> Запекание (lightmaps, probes) и типы источников — **общие**. Различается именно способ применения реалтайм-света при отрисовке.
