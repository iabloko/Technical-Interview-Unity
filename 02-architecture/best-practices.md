# Лучшие практики: DRY / KISS

Принципы, которые помогают держать код простым и без дублирования. В отличие от [SOLID](solid.md) (про структуру классов), это общие правила «здравого смысла» при ежедневном написании кода.

---

## KISS — Keep It Simple, Stupid

> Делай настолько просто, насколько возможно, но не проще. Простое решение почти всегда лучше «умного».

Сложность — главный враг поддерживаемости: её труднее читать, тестировать и менять. Не добавляй абстракции и обобщённость «на будущее», пока в них нет реальной нужды.

```csharp
// плохо: фабрика и интерфейс ради единственного типа врага
public interface IEnemyFactory { Enemy Create(); }
public class GoblinFactory : IEnemyFactory { public Enemy Create() => new Goblin(); }
var enemy = new GoblinFactory().Create();

// хорошо: пока враг один — просто создаём его
var enemy = new Goblin();
```

Признаки нарушения KISS:
- абстракции и слои, у которых одна реализация;
- «универсальные» методы с кучей флагов-параметров (`bool`, `enum`), меняющих поведение;
- паттерны ради паттернов;
- хитрые однострочники вместо понятного кода.

## DRY — Don't Repeat Yourself

> У каждого фрагмента **знания** должен быть один авторитетный источник в системе.

Дублирование опасно тем, что при изменении логики легко поправить одну копию и забыть остальные → баги. Повторяющуюся логику выносят в метод/класс/конфиг.

```csharp
// плохо: формула урона скопирована в трёх местах
float melee  = baseDmg * (1 + strength * 0.1f);
float ranged = baseDmg * (1 + strength * 0.1f);
float magic  = baseDmg * (1 + strength * 0.1f);

// хорошо: единый источник истины
float Damage(float baseDmg, float strength) => baseDmg * (1 + strength * 0.1f);
```

В Unity DRY-данные часто выносят в **ScriptableObject** — один ассет с настройками вместо разбросанных по коду констант.

### Важная оговорка: не «пересушить» (DRY ≠ убрать любое сходство)

DRY — про дублирование **знания**, а не про внешне похожий код. Если два куска *случайно* выглядят одинаково, но описывают **разные** правила, объединять их **не нужно** — иначе одна абстракция начнёт обслуживать два расходящихся сценария (это нарушит и KISS).

> Эмпирика: терпи дублирование до 2-3 повторений; объединяй, когда увидел *настоящую* общую логику, а не совпадение.

## Родственный принцип: YAGNI

**You Aren't Gonna Need It** — не реализуй функциональность, пока она реально не понадобилась. Тесно связан с KISS: оба борются с преждевременным усложнением. (Можно вынести в отдельную тему при необходимости.)
