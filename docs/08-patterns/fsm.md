# Конечный автомат (FSM, State Machine)

FSM (конечный автомат) — модель поведения: объект имеет конечный набор состояний, в каждый момент активно одно, переходы между ними определены правилами. Реализуется через `enum` + `switch`, таблицу переходов или паттерн **State** (каждое состояние — объект). Снимает «лес `if/switch`» в логике поведения (AI, анимация, игровой режим, UI-флоу).

## Понятия

- **State** — состояние (Idle, Patrol, Chase, Attack, Dead).
- **Transition** — переход из одного состояния в другое по условию/событию.
- **Context** — объект, чьё поведение управляется автоматом.

## Реализация через интерфейс состояний

Каждое состояние — класс с `Enter`/`Update`/`Exit`. Это соответствует [OCP](../02-architecture/solid.md): новое состояние добавляется новым классом, без правки существующих.

```csharp
public interface IState
{
    void Enter();
    void Tick();
    void Exit();
}

public class StateMachine
{
    private IState _current;

    public void Change(IState next)
    {
        _current?.Exit();
        _current = next;
        _current.Enter();
    }

    public void Tick() => _current?.Tick();
}
```

`Enter`/`Exit` — ключевая выгода: вход/выход из состояния инкапсулирован (запустить анимацию в `Enter`, отписаться в `Exit`), не распределён по условиям.

## Виды

- **Простой FSM** — одно активное состояние. Достаточно для большинства задач.
- **Hierarchical FSM (HFSM)** — состояния вложены (например, `Combat` содержит `Attack`/`Block`), общие переходы поднимаются на родителя — меньше дублирования.
- **Pushdown automaton** — стек состояний: можно «вернуться» в предыдущее (пауза поверх геймплея, затем возврат).

## Где в Unity уже есть FSM

- **Animator (Mecanim)** — визуальный FSM для анимаций (состояния, переходы, параметры).
- Для геймплейной логики обычно пишут свой код-FSM (Animator для логики неудобен).

## Связь с другими подходами

- **State vs Strategy** (см. [паттерны](design-patterns.md)): Strategy — взаимозаменяемые алгоритмы по выбору клиента; State — поведение меняется самим объектом при смене внутреннего состояния, состояния «знают» о переходах.
- На сложных деревьях решений для AI вместо FSM применяют **Behaviour Tree** (лучше масштабируется на много действий).

## Что спрашивают на собеседовании

- Зачем FSM (убрать разросшиеся `if/switch`, инкапсуляция входа/выхода).
- Что дают `Enter`/`Exit`.
- Как FSM соотносится с OCP (новое состояние = новый класс).
- Разница State vs Strategy.
- Когда FSM не хватает (HFSM, pushdown, behaviour tree).
