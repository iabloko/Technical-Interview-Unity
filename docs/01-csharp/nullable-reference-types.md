# Nullable reference types (NRT)

Опциональная функция компилятора (C# 8+), делящая ссылочные типы на «может быть null» и «не должен быть null». Цель — выявлять потенциальные `NullReferenceException` на этапе компиляции.

## Синтаксис

При включённом контексте: `#nullable enable` в файле или `<Nullable>enable</Nullable>` в `.csproj` обычного .NET-проекта. В Unity `.csproj` генерируется редактором и правки в нём не сохраняются, поэтому для всей сборки добавляют `-nullable:enable` в файл `csc.rsp` рядом с `.asmdef`.

```csharp
string  name;     // non-nullable: присвоение null → предупреждение
string? maybe;    // nullable: компилятор требует проверки перед разыменованием
```

- `T?` — допускает `null`.
- `T` (без `?`) — компилятор считает, что `null` быть не должно, и предупреждает о нарушениях.

## Это только статический анализ

NRT — **подсказки компилятора, а не рантайм-гарантия.** В IL различия нет; в рантайме `null` по-прежнему может прийти (например, из кода без NRT, из рефлексии, из десериализации). Предупреждения не равны ошибкам и не меняют поведение.

## Операторы

| Оператор | Смысл |
|---|---|
| `?.` | null-conditional: вызов только если не null, иначе `null` |
| `??` | null-coalescing: значение по умолчанию, если левое null |
| `??=` | присвоить, только если переменная null |
| `!` | null-forgiving: «я гарантирую, что не null» — подавляет предупреждение |

`!` (null-forgiving) использовать осознанно: он лишь глушит анализатор, не проверяя ничего в рантайме.

## Специфика Unity

- В сериализуемых `[SerializeField]`-полях значение проставляет движок при десериализации, а не конструктор — компилятор этого «не видит» и предупреждает о non-nullable поле без инициализации. Обходы: инициализатор `= null!`, `= default!`, либо отключение NRT в этих местах.
- **Fake null** Unity (см. [equality](equality.md)): уничтоженный `UnityEngine.Object` сравнивается с `null` через перегруженный `==`, но для компилятора NRT он «не null». То есть NRT и Unity-семантика null расходятся — `?.` на Unity-объекте не учитывает fake null. Для Unity-объектов проверять `if (obj == null)` (перегрузка), а не полагаться на NRT.

## Что спрашивают на собеседовании

- Что даёт NRT и что это **не** рантайм-гарантия (только анализ компилятора).
- Разница `T` и `T?` в nullable-контексте.
- Что делает оператор `!` (null-forgiving) и чем опасен.
- Почему NRT конфликтует с `[SerializeField]` и с fake null в Unity.
