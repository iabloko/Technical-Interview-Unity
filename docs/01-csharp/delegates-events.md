# Делегаты, события, Action / Func, замыкания

## Делегат

Делегат — типобезопасный указатель на метод. Под капотом это класс, наследник `System.MulticastDelegate`, хранящий пару `(Target, MethodPtr)`: ссылку на экземпляр (`null` для статического метода) и адрес метода.

```csharp
public delegate float Operation(float a, float b);
Operation op = Mathf.Max;   // op.Target = null, op.Method = Mathf.Max
```

Многоадресность (multicast): один делегат хранит список вызовов (invocation list). `+=` добавляет, `-=` удаляет. При вызове методы выполняются по порядку; возвращается результат **последнего**.

## Action / Func / Predicate

Готовые обобщённые делегаты — свой `delegate`-тип объявлять не нужно.

| Тип | Сигнатура |
|---|---|
| `Action` | `void ()` |
| `Action<T1,…,T16>` | `void (args)` |
| `Func<…,TResult>` | возвращает `TResult` (последний параметр — тип результата) |
| `Predicate<T>` | `bool (T)` |

## Событие (event)

`event` — это модификатор поля-делегата, ограничивающий доступ извне: снаружи класса допустимы только `+=` и `-=`. Нельзя присвоить (`=`), вызвать (`Invoke`) или прочитать список подписчиков. Это инкапсуляция: подписчик не может затереть чужие подписки или спровоцировать вызов.

```csharp
public event Action<int> HealthChanged;

private void SetHealth(int v)
{
    _health = v;
    HealthChanged?.Invoke(v);   // вызывать может только владелец
}
```

`?.Invoke` защищает от `NullReferenceException`, когда подписчиков нет (`event` равен `null`).

## Замыкания (closures)

Лямбда, захватывающая внешнюю переменную, образует замыкание. Компилятор генерирует **скрытый класс** (display class), переносит захваченные переменные в его поля, а лямбду — в его метод. Аллокаций две: экземпляр display class создаётся при входе в область видимости захваченной переменной (даже если лямбда в этом проходе не создаётся), экземпляр делегата — при каждом вычислении лямбда-выражения.

```csharp
void Apply(bool enabled)
{
    int bonus = 10;
    if (!enabled) return;

    Func<int, int> f = x => x + bonus;
    _total += f(5);
}
```

Код после компиляции (упрощённо; настоящие имена — `<>c__DisplayClass0_0`, `<Apply>b__0`):

```csharp
sealed class DisplayClass
{
    public int bonus;                          // захваченная переменная стала полем
    public int Lambda(int x) => x + bonus;     // тело лямбды стало методом
}

void Apply(bool enabled)
{
    var closure = new DisplayClass();          // аллокация 1: вход в область видимости bonus
    closure.bonus = 10;                        // все обращения к bonus идут через поле
    if (!enabled) return;                      // ранний выход: аллокация 1 уже произошла

    Func<int, int> f = new Func<int, int>(closure.Lambda);  // аллокация 2: экземпляр делегата
    _total += f(5);
}
```

| Лямбда | Display class | Делегат |
|---|---|---|
| без захвата: `x => x * 2` | нет | один раз при первом вычислении, затем берётся из статического поля |
| захватывает только `this` (поля и методы экземпляра) | нет: лямбда компилируется в метод текущего класса | при каждом вычислении |
| захватывает локальную переменную или параметр | при входе в область видимости переменной | при каждом вычислении |

Нюансы:

- **Захватывается переменная, а не значение.** Изменение переменной после создания лямбды видно внутри лямбды.
- **Цикловая ловушка**: переменная цикла `for` одна на весь цикл, поэтому все лямбды, захватившие её, видят значение после завершения цикла. До C# 5 то же происходило в `foreach`; начиная с C# 5 каждая итерация `foreach` получает свою переменную.
- Лямбда **без захвата** кешируется компилятором в статическое поле: делегат аллоцируется один раз при первом вычислении, затем переиспользуется.

## Подводные камни (важно для собеседования)

- **Утечки памяти через события.** Подписка `source.Event += handler` создаёт ссылку от источника к подписчику. Если источник живёт дольше — подписчик не собирается GC. Всегда отписываться (`-=`) в `OnDisable`/`OnDestroy`/`Dispose`.
- **Аллокации в hot path.** Захватывающая лямбда в `Update` или в колбэке, вызываемом каждый кадр, аллоцирует постоянно → нагрузка на GC. Выносить в закешированный делегат или использовать метод без захвата.
- **Исключение в одном подписчике** прерывает обход invocation list — последующие подписчики не получат вызов.
- `-=` сравнивает делегаты по `(Target, Method)`. Отписать лямбду можно только по сохранённой ссылке на тот же экземпляр делегата, не по новой идентичной лямбде.

## Что спрашивают на собеседовании

- Что такое делегат и как работает multicast (invocation list, результат последнего вызова).
- Чем `event` отличается от публичного поля-делегата.
- Что такое замыкание, что генерирует компилятор и где возникают аллокации.
- Ловушка захвата переменной цикла `for`.
- Почему события приводят к утечкам памяти и где отписываться в Unity.
