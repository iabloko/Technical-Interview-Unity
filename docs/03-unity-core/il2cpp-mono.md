# Scripting backend: Mono vs IL2CPP, AOT vs JIT

Scripting backend — способ, которым Unity превращает C#-код в исполняемый на устройстве.

## Mono (JIT)

C# → IL (промежуточный байткод) → IL выполняется виртуальной машиной Mono, которая **JIT-компилирует** IL в машинный код во время работы (Just-In-Time).

- Быстрая сборка (нет этапа компиляции C++).
- Доступен полный рантайм-функционал, включая генерацию кода.
- Доступен не на всех платформах: iOS запрещает JIT (нельзя исполнять код, сгенерированный в рантайме), поэтому там Mono недоступен.

## IL2CPP (AOT)

C# → IL → **транспиляция IL в C++** → нативный компилятор платформы собирает машинный код **заранее** (Ahead-Of-Time).

- Выше производительность исполнения и старта (нет JIT-прогрева).
- Сложнее реверс-инжиниринг (нет открытого IL).
- Обязателен для iOS, консолей, WebGL.
- Дольше собирается (компиляция C++).

## AOT vs JIT — суть отличия

| | JIT (Mono) | AOT (IL2CPP) |
|---|---|---|
| Когда компилируется | в рантайме | при сборке |
| Генерация кода в рантайме | можно | нельзя |
| Старт | прогрев JIT | сразу нативный |
| Платформы | где разрешён JIT | везде |

## Ограничения AOT (главное для собеседования)

Поскольку весь код порождается на этапе сборки, в рантайме нельзя создать новый:

- **`System.Reflection.Emit`** — генерация IL в рантайме не работает.
- **Generic virtual methods** и обобщения, конкретизированные только через рефлексию (`MakeGenericType`/`MakeGenericMethod`): если инстанциация с value-типом нигде не встречается в коде статически, IL2CPP не сгенерирует для неё код. До Unity 2022.1 это `ExecutionEngineException` («no ahead of time (AOT) code was generated») в рантайме; решение — статически упомянуть инстанциацию (например, в неиспользуемом методе-хелпере). `[Preserve]`/`link.xml` здесь не помогают: они запрещают удалять существующий код, но не порождают новые инстанциации. С Unity 2022.1 IL2CPP в таком случае вызывает полностью общую (full generic sharing) версию метода — без исключения, но медленнее специализированного кода.
- **Code stripping (managed stripping):** IL2CPP удаляет код, который считает недостижимым. Код, используемый только через рефлексию/сериализацию, может быть вырезан. Защита — `link.xml`, `[Preserve]`.
