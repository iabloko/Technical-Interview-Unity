# Memory Profiler

Отдельный пакет (`com.unity.memoryprofiler`, ставится через Package Manager). Делает **полные снимки памяти** запущенной игры — managed + native + ассеты — и позволяет их **сравнивать**. Главный инструмент для поиска **утечек** и понимания, на что уходит память.

## Как работает

- Открыть: **Window → Analysis → Memory Profiler**.
- Подключиться к редактору или билду (как у обычного Profiler).
- Нажать **Capture New Snapshot** (или **Capture** на панели инструментов) — игра кратко замирает, в файл сохраняется состояние всей памяти.
- Снимки перечислены в панели **Snapshots**: режим **Single Snapshot** открывает один снимок, режим **Compare Snapshots** — два для сравнения.

## Что ключевое можно посмотреть

Главная панель пакета 1.x состоит из трёх вкладок (вида Tree Map из пакета 0.x в 1.x нет):

- **Summary** — обзор распределения памяти приложения по категориям.
- **Unity Objects** — сколько native-, graphics- и managed-памяти занимает каждый тип Unity-объектов (текстуры, меши, аудиоклипы, шейдеры); отсюда — **топ-объекты по размеру**: самые тяжёлые текстуры и меши, типичная находка — забытый mipmap-флаг или несжатая 4K-текстура.
- **All Of Memory** — вся отслеживаемая память, не только Unity-объекты: managed heap, нативные аллокации, память вне объектов движка.

Дополнительно:

- **Managed heap** — общий размер и фрагментация; память пустых участков кучи Unity возвращает ОС лишь со временем и без гарантий по интервалу (см. [Unity GC](unity-gc.md)).
- **Referenced By** (в панели сведений о выбранном объекте) — кто держит ссылку на объект, мешая GC его выгрузить (классическая причина утечки: подписка на событие, статическое поле, синглтон).
- **Сравнение двух снимков** — главный приём для ловли утечек: снимок до и после действия (например, до загрузки сцены и после её выгрузки) → всё, что *осталось*, скорее всего, утекло.
- **Разница managed vs native** — managed считает GC, native (текстуры, меши, аудио) живёт отдельно и освобождается через `Destroy`/`Dispose`.

## Типичный workflow «ищем утечку»

1. Запустил билд, дождался стабильного состояния (главное меню).
2. **Capture snapshot A**.
3. Загрузил уровень → выгрузил уровень → вернулся в меню.
4. **Capture snapshot B**.
5. **Compare Snapshots** A и B — всё, что появилось и **не исчезло**, потенциальная утечка.
6. По **Referenced By** смотришь, **кто** держит ссылку — и идёшь в код чинить.

## Чем отличается от обычного Profiler

|                     | Profiler (Memory модуль)         | Memory Profiler                         |
|---------------------|----------------------------------|-----------------------------------------|
| Тип данных          | поток метрик во времени          | полный **снимок** в момент Capture      |
| Глубина             | агрегированные цифры             | объект-за-объектом, граф ссылок         |
| Сравнение состояний | нет                              | **да** (diff двух снимков)              |
| Когда использовать  | следить за расходом по ходу игры | искать **утечки** и крупные потребители |

## Что спрашивают на собеседовании

- Чем Memory Profiler отличается от модуля Memory в Profiler.
- Как найти утечку сравнением двух снимков.
- Как узнать, что удерживает объект в памяти (Referenced By).
- Что обычно занимает больше всего памяти и типичные причины (несжатые текстуры, лишние mipmaps).
- Почему managed heap в Unity растёт и не уменьшается сразу после сборок (фрагментация, возврат памяти ОС без гарантий по времени).
