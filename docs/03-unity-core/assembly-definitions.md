# Assembly Definitions (.asmdef)

По умолчанию весь код в `Assets/` компилируется в две сборки: `Assembly-CSharp` (runtime) и `Assembly-CSharp-Editor`. Файл `.asmdef` объявляет отдельную сборку из папки и её подпапок с явным списком зависимостей.

## Зачем

- **Скорость компиляции.** Изменение в одной сборке перекомпилирует только её и зависящие от неё, а не весь проект. На крупном проекте это разница в секундах vs десятки секунд на каждое изменение.
- **Изоляция и контроль зависимостей.** Сборка видит только то, что указано в `References`. Это инструмент архитектуры: можно физически запретить, чтобы слой данных ссылался на UI (см. [coupling](../02-architecture/coupling-decoupling.md), [SOLID](../02-architecture/solid.md)).
- **Платформенная фильтрация.** Сборку можно ограничить платформами или Editor-only.
- **Тесты.** Тестовые сборки (`Unity.TestRunner`-references) выносятся отдельно и не попадают в билд (см. [тестирование](../09-testing/testing.md)).

## Ключевые настройки

| Поле | Смысл |
|---|---|
| `References` | от каких других asmdef зависит |
| `Auto Referenced` | подхватывается ли автоматически в `Assembly-CSharp` |
| `Platforms` | include/exclude по платформам |
| `Define Constraints` | компилировать только при заданных `#define` |
| `Allow unsafe code` | разрешить `unsafe` |
| `No Engine References` | не ссылаться на сборки UnityEngine/UnityEditor — для слоя на чистом C# (см. [Clean Architecture](../02-architecture/clean-architecture.md)) |
| `Version Defines` | `#define` в зависимости от версии пакета |

## asmref

`.asmref` (Assembly Definition Reference) добавляет папку в **существующую** сборку, не создавая новую. Полезно, когда части одной логической сборки лежат в разных местах дерева.

## Подводные камни

- Циклические зависимости между сборками запрещены — Unity не скомпилирует. Это вынуждает продумывать направление зависимостей (полезно).
- `internal` виден внутри одной сборки; разбиение на asmdef меняет видимость. `[assembly: InternalsVisibleTo("…")]` открывает internal тестовой сборке.
- Слишком мелкое дробление даёт накладные расходы на линковку; слишком крупное — теряет выигрыш инкрементальной компиляции.

## Что спрашивают на собеседовании

- Зачем нужны asmdef (скорость компиляции, контроль зависимостей).
- Как asmdef помогает архитектуре (запрет нежелательных ссылок между слоями).
- Чем `.asmref` отличается от `.asmdef`.
- Почему циклические зависимости сборок невозможны и почему это хорошо.
