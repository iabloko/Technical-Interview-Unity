# Обобщения (Generics): ограничения и вариантность

Обобщения позволяют писать код, параметризованный типом (`List<T>`, `Dictionary<K,V>`). Это [параметрический полиморфизм](oop.md): один алгоритм для любого типа без боксинга и приведений.

## Как CLR реализует generics

- Для **value-типов** JIT генерирует отдельный специализированный машинный код под каждый тип (`List<int>` и `List<float>` — разный код). Нет боксинга.
- Для **ссылочных типов** используется одна общая реализация (ссылки одного размера).

Это отличает .NET от Java (стирание типов, type erasure): в .NET информация о типовом аргументе доступна в рантайме (`typeof(T)`).

## Ограничения (constraints)

Сужают допустимые типовые аргументы и дают доступ к их членам:

| Ограничение | Смысл |
|---|---|
| `where T : class` | ссылочный тип |
| `where T : struct` | non-nullable value-тип |
| `where T : new()` | есть открытый конструктор без параметров |
| `where T : BaseClass` | наследник класса |
| `where T : IInterface` | реализует интерфейс |
| `where T : U` | T наследует/реализует другой параметр U |
| `where T : unmanaged` | value-тип без ссылок (нужно для `NativeArray`, [Burst](../07-dots/jobs-burst.md)) |
| `where T : notnull` | не допускает nullable |

```csharp
public T Create<T>() where T : Component, new() => new T();
```

Без ограничения с типом `T` можно делать минимум (как с `object`); ограничение открывает его API на этапе компиляции, без рефлексии и боксинга.

## Вариантность: in / out

Применима только к **интерфейсам и делегатам**, не к классам.

- **Ковариантность (`out`)** — параметр используется только как результат. `IEnumerable<out T>`: `IEnumerable<Dog>` присваивается `IEnumerable<Animal>` (от частного к общему).
- **Контравариантность (`in`)** — параметр используется только как вход. `IComparer<in T>`, `Action<in T>`: `Action<Animal>` присваивается `Action<Dog>` (от общего к частному).
- **Инвариантность** — без модификатора. `List<Dog>` **не** является `List<Animal>` (иначе можно было бы положить туда `Cat`).

```csharp
IEnumerable<Animal> animals = new List<Dog>();   // ковариантность, ОК
Action<Dog> a = (Action<Animal>)(x => Feed(x));   // контравариантность, ОК
```

Мнемоника: `out` = тип на выходе → ковариантность; `in` = тип на входе → контравариантность.

## Что спрашивают на собеседовании

- Чем generics в .NET отличаются от Java (специализация vs стирание типов, доступ к `T` в рантайме).
- Почему `List<Dog>` нельзя присвоить `List<Animal>` (инвариантность, нарушение безопасности).
- Что такое ко-/контравариантность и где `in`/`out`.
- Зачем нужны constraints и что даёт `where T : unmanaged`.
