# Span&lt;T&gt;, Memory&lt;T&gt;, ref struct, stackalloc

Инструменты для работы с непрерывными участками памяти **без аллокаций в куче** и без копирования.

## Span&lt;T&gt;

`Span<T>` — типобезопасное представление непрерывного участка памяти: участка массива, стекового буфера или неуправляемой памяти. Хранит ссылку на начало и длину. Срез (`Slice`) не копирует данные — это окно в те же байты.

```csharp
int[] arr = { 1, 2, 3, 4, 5 };
Span<int> middle = arr.AsSpan(1, 3);   // {2,3,4}, без копии
middle[0] = 20;                         // меняет arr[1]
```

`ReadOnlySpan<char>` особенно полезен для парсинга строк без аллокаций: `substring` создаёт новую строку, срез по `ReadOnlySpan<char>` — нет.

## ref struct

`Span<T>` объявлен как `ref struct` — тип, который **может жить только на стеке**. Ограничения:
- Нельзя сделать полем класса (поле обычного класса живёт в куче).
- Нельзя боксировать.
- Нельзя захватывать в лямбду/замыкание.
- Нельзя использовать в `async`-методах и в `yield`-итераторах (их состояние сохраняется в куче).

Это и обеспечивает безопасность: `Span` не может пережить память, на которую указывает.

## Memory&lt;T&gt;

`Memory<T>` — «куче-совместимый» аналог `Span<T>`. Может быть полем класса, использоваться в `async`. Доступ к данным — через свойство `.Span`. Применяют, когда участок памяти нужно хранить или передавать через асинхронные границы.

## stackalloc

Выделяет буфер на стеке — без аллокации в куче и без работы GC. Память освобождается автоматически при выходе из метода.

```csharp
Span<byte> buffer = stackalloc byte[256];   // на стеке, без GC
```

Только для малых буферов: стек ограничен (переполнение → `StackOverflowException`). Типичный размер — сотни байт, не мегабайты.

## Связь с Unity

- Снижение GC-аллокаций в hot path — прямая выгода для частоты кадров (см. [Unity GC](../03-unity-core/unity-gc.md)).
- `NativeArray<T>` в [Job System](../07-dots/jobs-burst.md) тоже даёт `AsSpan()`.
- Парсинг текста/сетевых данных без промежуточных строк и `byte[]`.

## Что спрашивают на собеседовании

- Зачем нужен `Span<T>` (доступ к памяти без копий и аллокаций).
- Почему `Span<T>` нельзя сохранить в поле класса или использовать в `async` (это `ref struct`, живёт только на стеке).
- Чем `Memory<T>` отличается от `Span<T>` (можно хранить и использовать в async).
- Что делает `stackalloc` и почему только для малых размеров.
