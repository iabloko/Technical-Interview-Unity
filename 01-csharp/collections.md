# Коллекции: List, Dictionary, HashSet и сложность операций

## Обзор и сложность

| Коллекция | Внутри | Доступ по индексу | Поиск | Вставка | Удаление |
|---|---|---|---|---|---|
| `T[]` | непрерывный блок | O(1) | O(n) | — (фикс. размер) | — |
| `List<T>` | массив + `Count`/`Capacity` | O(1) | O(n) | O(1) амортизир. в конец; O(n) в середину | O(n) |
| `Dictionary<K,V>` | хеш-таблица (бакеты + entries) | — | O(1) средн., O(n) худший | O(1) амортизир. | O(1) |
| `HashSet<T>` | хеш-таблица | — | O(1) средн. | O(1) амортизир. | O(1) |
| `LinkedList<T>` | двусвязный список узлов | O(n) | O(n) | O(1) при наличии узла | O(1) при наличии узла |
| `Queue<T>` / `Stack<T>` | кольцевой массив / массив | — | O(n) | O(1) амортизир. | O(1) |
| `SortedDictionary<K,V>` | красно-чёрное дерево | — | O(log n) | O(log n) | O(log n) |
| `SortedList<K,V>` | два отсортированных массива (ключи/значения) | O(1) (`Keys[i]`, `Values[i]`) | O(log n) | O(n) | O(n) |

## List<T>

Обёртка над массивом. `Count` — число элементов, `Capacity` — размер внутреннего массива. При добавлении сверх `Capacity` создаётся новый массив (обычно ×2) и элементы копируются → разовая O(n) и аллокация. Поэтому при известном размере задавать `new List<T>(capacity)` заранее.

- Удаление/вставка в середину сдвигает «хвост» — O(n).
- `RemoveAt(last)` — O(1).
- Перечисление `List<T>` использует **struct-энумератор** → `foreach` по `List<T>` не аллоцирует. Но если перечислять через `IEnumerable<T>`, энумератор боксируется → аллокация.

## Dictionary<K,V>

Хеш-таблица. Для ключа вычисляется `GetHashCode()`, по нему — номер бакета (`hash % capacity`). В бакете элементы с одинаковым индексом образуют цепочку (через массив `entries` и поле `next`). Сравнение ключей — через `EqualityComparer<K>.Default` (`Equals`).

- **Корректные `GetHashCode`/`Equals` обязательны.** Плохой хеш (много коллизий) вырождает поиск в O(n).
- Ключ-`struct` без переопределённого `GetHashCode` использует рефлексивную реализацию `ValueType.GetHashCode` — медленную и с боксингом. Для struct-ключей реализовывать `IEquatable<T>` и `GetHashCode`.
- Порядок перечисления не гарантирован.
- `enum` как ключ до .NET Core вызывал боксинг в компараторе; в современных рантаймах оптимизировано.

## HashSet<T>

Та же хеш-таблица, но хранит только ключи. Быстрая проверка принадлежности `Contains` за O(1) и операции над множествами (`UnionWith`, `IntersectWith`, `ExceptWith`).

## Что спрашивают на собеседовании

- Чем `List` отличается от массива (динамический размер, рост `Capacity`).
- Почему `Dictionary` даёт O(1) и когда деградирует до O(n) (коллизии хешей).
- Зачем переопределять `GetHashCode` вместе с `Equals` для ключей.
- Аллокации при `foreach`: `List<T>` через конкретный тип не аллоцирует, через интерфейс — да.
- `Array` vs `List` vs `Dictionary` по производительности и сценарию использования.
