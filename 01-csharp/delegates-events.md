# Делегаты, события, Action / Func, замыкания

## Делегат

Делегат — типобезопасный указатель на метод. Под капотом это класс, наследник `System.MulticastDelegate`, хранящий пару `(Target, MethodPtr)`: ссылку на экземпляр (`null` для статического метода) и адрес метода.

```csharp
public delegate float Operation(float a, float b);
Operation op = Mathf.Max;   // op.Target = null, op.Method = Mathf.Max
```

Многоадресность (multicast): один делегат хранит список вызовов (invocation list). `+=` добавляет, `-=` удаляет. При вызове методы выполняются по порядку; возвращается результат **последнего**.

## Action / Func / Predicate

Готовые обобщённые делегаты — свой `delegate`-тип объявлять не нужно.

| Тип | Сигнатура |
|---|---|
| `Action` | `void ()` |
| `Action<T1,…,T16>` | `void (args)` |
| `Func<…,TResult>` | возвращает `TResult` (последний параметр — тип результата) |
| `Predicate<T>` | `bool (T)` |

## Событие (event)

`event` — это модификатор поля-делегата, ограничивающий доступ извне: снаружи класса допустимы только `+=` и `-=`. Нельзя присвоить (`=`), вызвать (`Invoke`) или прочитать список подписчиков. Это инкапсуляция: подписчик не может затереть чужие подписки или спровоцировать вызов.

```csharp
public event Action<int> HealthChanged;

private void SetHealth(int v)
{
    _health = v;
    HealthChanged?.Invoke(v);   // вызывать может только владелец
}
```

`?.Invoke` защищает от `NullReferenceException`, когда подписчиков нет (`event` равен `null`).

## Замыкания (closures)

Лямбда, захватывающая внешнюю переменную, образует замыкание. Компилятор генерирует **скрытый класс** (display class), переносит захваченные переменные в его поля, а лямбду — в его метод. Это означает аллокацию в куче на каждом создании замыкания.

```csharp
int bonus = 10;
Func<int, int> f = x => x + bonus;   // bonus захвачен → аллокация display-класса
```

Нюансы:
- **Захватывается переменная, а не значение.** Изменение переменной после создания лямбды видно внутри лямбды.
- **Цикловая ловушка** (до C# 5 — `for`, и сейчас в `for`): захват переменной цикла даёт всем лямбдам одно общее значение. В `foreach` начиная с C# 5 каждая итерация имеет свою переменную.
- Лямбда **без захвата** кешируется компилятором в статическое поле — аллокации нет.

## Подводные камни (важно для собеседования)

- **Утечки памяти через события.** Подписка `source.Event += handler` создаёт ссылку от источника к подписчику. Если источник живёт дольше — подписчик не собирается GC. Всегда отписываться (`-=`) в `OnDisable`/`OnDestroy`/`Dispose`.
- **Аллокации в hot path.** Захватывающая лямбда в `Update` или в колбэке, вызываемом каждый кадр, аллоцирует постоянно → нагрузка на GC. Выносить в закешированный делегат или использовать метод без захвата.
- **Исключение в одном подписчике** прерывает обход invocation list — последующие подписчики не получат вызов.
- `-=` сравнивает делегаты по `(Target, Method)`. Отписать лямбду можно только по сохранённой ссылке на тот же экземпляр делегата, не по новой идентичной лямбде.
